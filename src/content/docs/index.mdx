## Install in a minute

<Tabs syncKey="os">
<TabItem label="macOS / Linux">
```bash
brew install adriandeleon/tap/jkit
jkit hook --install --auto-switch   # then open a new shell
jkit install jdk@21                 # the first JDK you install becomes the default
```
</TabItem>
<TabItem label="Debian / Ubuntu">
```bash
# after adding the Vitrina apt repository (see Install)
sudo apt install jkit
jkit hook --install --auto-switch   # then open a new shell
jkit install jdk@21
```
</TabItem>
<TabItem label="Windows (preview)">
```powershell
winget install AdrianDeLeon.jkit
# add the hook to your PowerShell profile: see Install
jkit install jdk@21
```
</TabItem>
</Tabs>

Fedora and RHEL packages, the Alpine (musl) build, plain binaries and building from source are
on the [install page](/start/install/).

## Why jkit

<CardGrid>
  <Card title="One native binary" icon="rocket">
    No JDK, no bash scripts, no plugins. It starts in milliseconds and runs the same way on Linux,
    macOS and Windows.
  </Card>
  <Card title="20+ vendors, one grid" icon="list-format">
    Temurin, Corretto, Zulu, Liberica, Oracle, GraalVM, SapMachine, Semeru, Microsoft and more.
    `jkit search jdk` shows them all against every major version.
  </Card>
  <Card title="Shell, project or global" icon="setting">
    `jkit use` for this shell, a `jkit.toml` for the project, `--global` for everything else.
    One clear order between them, and `jkit status` says which one won.
  </Card>
  <Card title="Nothing changes quietly" icon="information">
    Every variable, `PATH` entry, link and file a command touches is printed, even when the shell
    switches JDK on `cd`.
  </Card>
  <Card title="Checked downloads" icon="approve-check">
    HTTPS only, checked against the publisher's checksum, and for Temurin, Microsoft, Corretto,
    Maven 3.9+ and sbt against their signature too. A download jkit can't check isn't installed
    unless you say so.
  </Card>
  <Card title="Ready for CI and AI agents" icon="laptop">
    It never prompts. `jkit exec -- mvn verify` runs one command with the project's versions;
    `--json` and stable exit codes make it easy to script.
  </Card>
</CardGrid>

## Compared with what you use today

|  | jkit | Manual install | SDKMAN | mise / asdf | OS packages |
| --- | --- | --- | --- | --- | --- |
| Installs JDKs from 20+ vendors | ✓ | by hand | ✓ | through a plugin | your distro's builds |
| Maven, Gradle and sbt | ✓ | by hand | ✓ | through plugins | some |
| Runs without bash; native on Windows | ✓ | – | needs bash | varies | – |
| Per-project versions, switch on `cd` | ✓ | – | ✓ | ✓ | – |
| Reads `.sdkmanrc`, `.tool-versions`, `.java-version` | all three | – | its own | its own + some | – |
| Refuses downloads with no checksum | ✓ | up to you | varies | varies | ✓ |
| Never prompts; `--json` output | ✓ | – | – | partly | – |

The [full comparison](/why/overview/) explains each row, and when another tool is the better fit.
